# 候选参考的诊断证据（不是模型成绩）

这里保留每次独立控制资格运行，包括完整通过、物理或端点拒绝、环境失败。它们不进入模型成功率，不自动加入任务 catalog，也不证明某题已足够困难。尤其，H201 的旋纸恢复路径与原路径、收紧求解精度对照是不同控制条件，不能择优合并。H207 只有明确中段范围；H202 是接口资格，不是模型图解题。

## 完整与未完成

只导出有 `qualification-complete.json`、且它的原始报告哈希/UUID/status 与 `qualification-plan.json` 相符的运行。封存表示运行记录已经结束，包括失败；不等于参考动作通过。环境失败可能只有准备记录而没有完整主任务轨迹，不能补造缺少的数据。没有完成标记的运行仅在派生索引中记为跳过，待其真实结束后才追加目录。

## 原始哈希与公开哈希

每个运行和草稿目录的 `export-manifest.json` 记录 `original_sha256` 与 `export_sha256`、字节数和 `transformed`。JSON 会递归替换本机/远程根路径、凭证连接标签，并压缩空白；数值不取整。数值 NPZ 原样复制并检查数据类型。原始报告、完成标记、计划内的哈希原封不动，仍指向**原始本地字节**，不能直接拿它校验脱敏报告。公开文件请对照 `export_sha256`；完成标记中的 `report_sha256` 应对应映射表里报告的 `original_sha256`。不伪造新的完成标记，不修改原始运行。

路径 `<PROJECT_ROOT>` 与 `<REMOTE_ROOT>` 是脱敏占位符。自有代码快照也有单独原/导出哈希；修改过路径的快照不声称仍具有原哈希。原计划中的源文件、物理后端、网格与控制器哈希继续保留。复制给他人后先配置他们自己的运行根与后端，不要直接执行含占位符的历史快照。

## 来源准备与复现边界

每份任务/运行有 `source-acquisition.json`，保留原页哈希、取图方式和来源链接；包中无 PNG/PDF、数据库、密钥、API 请求或原始日志。

- H201 使用本仓库已有的原创 O02/O03 图解；按来源清单指向 `data/release-v1/public/diagrams`，不重复打包。
- H207 从 NASA 官方 PDF 获取并本地渲染第19/20页；参考任务只到第20页第一行，不是完整飞机。按上游条款获取素材，再在工作副本中替换 `pages` 路径。不同渲染器未必产生原缓存字节；应核对内容/页码，并明确记录自己的源图哈希，不能冒充原运行输入。
- H202 原创静态示意图没有打包。若需要图像，可从 `diagnostic-tasks/H202/static-minimal-columns2.npz` 绘制并明确标为理想几何、示意高度放大；不得当作真实物理回放或新增模型题。数值参考动作不依赖看图，这仍是接口资格。

`diagnostic-tasks/` 只归档 public/private 草稿、必要网格和数值注释；没有登记到正式 catalog。`static-*` 永远是静态注释。真实准备态、目标、检查点和拒绝候选保存在对应运行目录的数值文件中；带 `prefix` 的只覆盖已保留前缀。失败记录不会因此变成完整目标。

复现参考需在工作副本中准备来源、重新绑定资产路径、选择同一控制器/物理签名与对应动作变体，并独立启动新的运行。此包仅保存证据，不自动运行物理，也不把重放结果等同于模型表现。严格精度对照还须使用其计划中的求解容差，其他材料/验收门槛保持原值。

## 追加与检查

每个已导出运行是只增不改；源记录或导出字节发生变化时，导出器拒绝覆盖。`export-snapshots/` 保留每次索引快照，`index.json` 仅是最新派生指针。继续运行中的候选由项目本地 `export_candidate_evidence.py` 在获得真实完成标记后追加；不需要写死新运行名。公开包内不会启动此脚本。
